# Offline TDX verification

`verify` consumes bounded raw Intel quote, QVL collateral JSON, dstack TDX event-log JSON, caller-expected service public keys, verifier-issued nonce, intended role, and a trusted conservative absolute time interval with caller-owned uncertainty limit. It checks Intel production root/chain/CRLs/TCB and strict UpToDate at **both** interval ends, nondebug/nonprofiled/nonmigratable TDX attributes, PPID length, exact report_data binding, and complete dstack RTMR3 SHA-384 replay with one 32-byte compose SHA-256 event. Boot measurements come from the verified quote. QVL is explicitly ring-based, without its network/report feature; the event-log implementation is pinned source in `../../third_party/dstack`.

Only this library constructs `Measured`; it returns bound public keys, policy `Build` and SHA-256 of authenticated 16-byte PPID. It does **not** prove private-key possession, issue nonce challenges, authenticate a channel, authorize signed policy freshness/rollback or jobs, release keys, fetch collateral, read wall time or network, or produce a ready-host capability. The caller must invoke the signed policy gate separately, using its own trusted time and current authority before every operation. Valid archived quote/collateral and separate event-log fixtures test independent halves; no matched fresh attestation is proven here. There is no Wasm claim.

The issuer must pass exactly the 64 raw bytes from `report_data` to TDX GetQuote without SDK rehashing. Domain and framing are versioned here; changing them breaks interoperability and requires a deliberate protocol revision. Bounds before parsing are 1 MiB for each input, 4096 events and 64 KiB per event payload. These leave space beyond archived fixtures (5 KiB quote, 16 KiB collateral, <19 KiB log) but require a later real-host sizing check before deployment. Caller transport must enforce its own byte limits. Errors carry no content from evidence or QVL.
