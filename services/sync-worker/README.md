# Internal Worker SQLite consumption adapter

`bh-sync-worker` runs the same `bh-sync::plan_consumption` as the native adapter inside a locally tested workerd module. `src/worker.mjs` implements one per-base SQLite Durable Object, with no public access endpoint: its default `fetch` returns 404. `consume` is internal DO RPC for a future authenticated host, **not** an access credential. There is no production provisioning route or deploy-ready config. `tests/sync-worker/fixture.mjs` alone provides test-only provisioning, tampering and request transport; do not deploy it. Fixture signatures are made by the native-only Rust example. The Worker module uses only BLAKE2b hash and Ed25519 verification in root-pinned `bh-crypto` and the unchanged `libs/crypto/worker-host.mjs` import whitelist; no Worker signing key exists.

The DO reads its gate and selected stored rows inside `transactionSync`, passes bounded versioned input to Rust, and compares the complete gate before updating event/index/sequence/last outcome in the same SQL transaction. Rust strictly decodes canonical lowercase hex, events, commitments, signed approval, exact operation, selected records and predecessor; it returns a plan, never writes SQL. A missing read body or corrupt indexed body refuses. An unindexed event id is eligible for first insertion only if the replay lookup completed; SQL errors fail closed. JS only extracts the event id/digest from Rust's canonical commitment for insert, never computes another hash. This first adapter keeps complete history in SQL and does not implement archival or batches. Its JS SQLite integer interface refuses numbers outside safe integer range rather than round a `u64` head or sequence.

The same Rust planner handles detached bodies from a separate SQL table keyed by the commitment Rust derives from the exact bytes. The DO takes an appended descriptor's first 32 envelope bytes as the body reference, looks it up, and Rust fails the append unless that exact body is staged; it acknowledges only after the transaction commits. Staging one body and reading 1–64 exact bodies each consume their own access sequence under distinct operation domains; an exact repeat stage is idempotent. A failed append may leave an unreferenced orphan body, never an acknowledged descriptor without its body. Corrupt stored body bytes refuse a read. JS never hashes; it only slices the reference, looks up rows and writes the Rust-provided commitment/bytes.

Cloudflare's documented `transactionSync` rolls back when its synchronous callback throws; only after it returns and `await ctx.storage.sync()` resolves does the adapter return an Ack or exact selected ciphertext. A local SQL trigger test confirms rollback. This uses the actual Miniflare/workerd SQLite DO API, not native rusqlite and not a deployed Cloudflare durability proof. See [Cloudflare SQLite-backed Durable Object storage API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/#transactions) (`transactionSync` and `sync`). The local restart fixture persists DO SQLite across Miniflare process recreation; it does not establish host recovery, rollback resistance or receipt authentication.

**Not supplied:** checker-issued pinned-key provisioning, a genuine one-use encrypted response channel (binding is supplied by the *test harness*), a qualified conservative clock (test time is synthetic), current signed account/audience authority, effective-removal serialization, a durable protected pending lane, authenticated checker receipts, live state freshness, attested transport or a deployed endpoint. Therefore this module must not serve real requests yet. Native `services/sync` still handles native SQLite. A stalled commit can outlive expiry, as documented in `../../libs/sync/PROTOCOL.md`; no arbitrary margin repairs it. The ordinary DO schema contains no member, device or private-chat handle. Bounded SQL archival and operation batching remain deferred.

From `basehero/` run `nix develop --command bash scripts/check.sh wasm-sync` for native-signed fixture generation, a pinned Worker-target build, an import audit and local SQLite DO scenarios. Also run `nix develop --command bash scripts/check.sh` and `nix develop --command bash scripts/check.sh wasm-crypto`. The `wasm-sync` check needs the existing Linux `.#cryptoWorker` shell and test-only pinned Miniflare package; it creates ignored `services/sync-worker/sync_worker.wasm` and `tests/sync-worker/fixtures.json`, with no paid call, remote deployment or account change.
