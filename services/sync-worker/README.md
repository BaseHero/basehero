# Internal Worker SQLite consumption adapter

`bh-sync-worker` runs the same `bh-sync::plan_consumption` as the native adapter inside a locally tested workerd module. `src/worker.mjs` implements one per-base SQLite Durable Object, with no public access endpoint: its default `fetch` returns 404. `consume` is internal DO RPC for a future authenticated host, **not** an access credential. There is no production provisioning route or deploy-ready config. `tests/sync-worker/fixture.mjs` alone provides test-only provisioning, tampering and request transport; do not deploy it. Fixture signatures are made by the native-only Rust example. The Worker module uses root-pinned `bh-crypto` under the unchanged `libs/crypto/worker-host.mjs` import whitelist; this adapter verifies only, and the only Worker signing key is the edge's receipt key below.

The DO reads its gate and selected stored rows inside `transactionSync`, passes bounded versioned input to Rust, and compares the complete gate before updating event/index/sequence/last outcome in the same SQL transaction. Rust strictly decodes canonical lowercase hex, events, commitments, signed approval, exact operation, selected records and predecessor; it returns a plan, never writes SQL. A missing read body or corrupt indexed body refuses. An unindexed event id is eligible for first insertion only if the replay lookup completed; SQL errors fail closed. JS only extracts the event id/digest from Rust's canonical commitment for insert, never computes another hash. This first adapter keeps complete history in SQL and does not implement archival or batches. Its JS SQLite integer interface refuses numbers outside safe integer range rather than round a `u64` head or sequence.

The same Rust planner handles detached bodies from a separate SQL table keyed by the commitment Rust derives from the exact bytes. The DO takes an appended descriptor's first 32 envelope bytes as the body reference, looks it up, and Rust fails the append unless that exact body is staged; it acknowledges only after the transaction commits. Staging one body and reading 1–64 exact bodies each consume their own access sequence under distinct operation domains; an exact repeat stage is idempotent. A failed append may leave an unreferenced orphan body, never an acknowledged descriptor without its body. Corrupt stored body bytes refuse a read. JS never hashes; it only slices the reference, looks up rows and writes the Rust-provided commitment/bytes.

Cloudflare's documented `transactionSync` rolls back when its synchronous callback throws; only after it returns and `await ctx.storage.sync()` resolves does the adapter return an Ack or exact selected ciphertext. A local SQL trigger test confirms rollback. This uses the actual Miniflare/workerd SQLite DO API, not native rusqlite and not a deployed Cloudflare durability proof. See [Cloudflare SQLite-backed Durable Object storage API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/#transactions) (`transactionSync` and `sync`). The local restart fixture persists DO SQLite across Miniflare process recreation; it does not establish host recovery, rollback resistance or receipt authentication.

**Not supplied:** checker-issued pinned-key provisioning, a genuine one-use encrypted response channel (binding is supplied by the *test harness*), a qualified conservative clock (test time is synthetic), current signed account/audience authority, effective-removal serialization, a durable protected pending lane, authenticated checker receipts, live state freshness, attested transport or a deployed endpoint. Therefore this module must not serve real requests yet. Native `services/sync` still handles native SQLite. A stalled commit can outlive expiry, as documented in `../../libs/sync/PROTOCOL.md`; no arbitrary margin repairs it. The ordinary DO schema contains no member, device or private-chat handle. Bounded SQL archival and operation batching remain deferred.

## Log object

`src/log.mjs` exports `LogObject`, one SQLite Durable Object per ordered log, named by the log's `kind:u8 || id:32` in hex (a base log or an account-home log). Its RPC methods are for the edge Worker only; its default `fetch` is a 404 and its own `fetch` serves only the internal `/subscribe` socket. It stores the ordered index (`events`, with each event's route: `control` is 1 for an append whose permit names a predecessor and 0 for content, the route Rust commits in its commitment), per-body staging state (`bodies`: `staging`, `ordered` or `reclaiming`) and `meta` (`log`, `epoch`, `head`, and `control`, the last ordered control's position and hash). Bodies live in the R2 bucket `BODIES` under `b/<log>/<commitment>`. It returns durable facts, never receipts.

- `storeHomeObjects(permit, bundle)` is an account-home-only immutable write to `private_home_objects(prefix_digest PRIMARY KEY, bundle_digest, bundle)`. Rust verifies the exact bounded bundle and signed prefix/digest binding at the edge and again at the object. The transaction inserts only if absent, accepts an exact retry, and refuses replacement as `Conflict`; it returns `{prefixDigest, bundleDigest}` only after storage sync, without an append position. These private ciphertexts have no read RPC, public body route or cleanup timer. The authorization service validates their original signed commitments before issuing the permission.
- `stage(permit, body)` and `append(permit, event)` verify the permit in Rust against the pinned `HOSTING_ROOT` at the object's clock, bind it to the exact bytes and to this object, and return `{ok}`, `{position, hash, eventId}` or `{refused}` with a data-wire refusal name.
- An append checks, in one transaction, the deadline, the exact-retry index (same id, digest and route returns the original result; same id with other bytes or on the other route is `Conflict`), then for a control that its predecessor is exactly the control head (else `Predecessor`), or for content that its epoch is the stored one and not closed (else `Epoch`), then a `staging` body row. Content ordered since the last control never moves the control head, so it cannot hold a control back. It then checks the R2 object's exact length with a HEAD, repeats every check in a second transaction that orders the event, and resolves only after `ctx.storage.sync()`. Rust computes the commitment.
- An ordered control sets the control head and sets the log's epoch to the one its permit names; all zeros means closed, and no content is admitted under it. The object never reads a control's content. An empty log has no epoch, so its first event is a control after the empty head, and Rust requires its digest to equal the log id. In an account-home log every event is a control, so the control head is the head.
- Staging writes the row before the object. The alarm marks staging rows older than 24 hours `reclaiming`, syncs, deletes their objects, then drops the rows, so no reclaimed object outlives its row; rows already `reclaiming` are resumed first. Staging a `reclaiming` body is refused with `Reclaiming`; ordered bodies are never reclaimed.
- Reads capture immutable rows and then await `ctx.storage.sync()`, just as append crosses that durability boundary before releasing its result. A sync failure releases no rows. This allocates no log position and holds no write transaction across the await. The edge signs the exact returned base tail, not the latest head; empty and account reads carry no receipt. Clients still judge the originals and content separately.
- `read(first, last)` returns up to 64 ordered `{commitment, event}` pairs, `controls(after)` up to 64 control-route pairs after that position in order (0 reads from the start), `orderedBodies(commitments)` the stored length of each of 1–64 bodies the edge may serve (else null): `ordered` ones, and in an account-home log also `staging` ones, never `reclaiming` ones, and `head()` the current head; none writes. The authorization service reads a rotation's staged body back before it permits the append; a device is granted an account body read only once the body is applied. `/subscribe` accepts a hibernating send-only socket of 40-byte `position || hash` notices.
- `/presence` accepts a hibernating socket tagged `presence` only if its `X-Bh-Epoch` header is the log's current, open epoch (else 409). Its attachment is `{epoch, slot}`, a random u32 unique among live sockets, and nothing else. The new socket gets a roster snapshot and the others `joined(slot)`; a closed socket's others get `left(slot)`. Each binary message of 1–512 opaque bytes is forwarded as `slot || bytes` to every other open presence socket at the current epoch, within per-base limits of 200 frames in and 5,000 sends out a second; a frame over either is dropped whole. Both limits are checked, the out one against the most sends the frame could need, before any socket's attachment is read, so a dropped frame costs no work per socket. Roster changes are outside these limits: each join or leave sends one 8-byte Peers to every other socket, so N devices rejoining together, as after a restart, cost about N² small sends once (about a million for 1,000 live devices). Limiting them would either lose a `left`, leaving a departed slot on others' rosters, or at 5,000 sends a second spread that rejoin over minutes. Head notices go only to `/subscribe` sockets. Ordering a control closes every presence socket with 4409. The presence path is synchronous: it awaits nothing, takes no transaction and uses no SQL, storage, R2 or console; the epoch it checks is kept in memory, loaded at construction and moved when a control is ordered. Rate buckets reset when the object hibernates.

The Wasm module exports `verify_permit`, `order_commitment`, `decode_request`, `read_tail` and `sign_head` beside the planner, sharing its input/result buffers and returning a refusal code or bounded JSON. `wrangler.local.toml` is a local Miniflare/workerd configuration with no account, route or deploy target. `tests/sync-worker/log-fixture.mjs` is test-only: it substitutes the clock, traces storage sync and injects crash and race points; permits come from the native-only `examples/permit_fixtures.rs`.

## Edge

`src/edge.mjs` is the Worker entry point named by `wrangler.local.toml`. It re-exports `LogObject` and `PairingRelay` and serves exactly three routes; any other path is 404, a non-upgrade request to a socket route is 426.

- `GET /v1/authz` upgrades to a WebSocket and opens one backend WebSocket to a ready entry of `AUTHZ_BACKENDS` (a JSON list of `{url, ready}`), rotating the first choice per connection. A backend that does not accept the upgrade within 2 s is skipped before any frame flows; the timeout covers only the upgrade, never the session. Binary frames are forwarded unchanged and never read. A connection stays pinned to its backend; if either side ends, both close and nothing is resent elsewhere, so a device retries through a new channel. Each session is charged its lasting cost against the isolate's memory budget (below) before any backend I/O, and the upgrade answers 503 if the budget cannot take it. The proxy never reads the channel, so identity is checked only by the backend, which closes a connection that has not upgraded within 5 s or authenticated a device within 30 s. A frame over 3,212,603 bytes closes with 1009 and a frame that would take the session past 8 MiB, both directions together, in a rolling 60 s closes with 1008 before it is forwarded, so a long session at a low rate stays open. A text frame closes with 1003, a second frame arriving while one is still being converted or an interrupted peer with 1011. With no ready backend accepting, the upgrade answers 503.
- `GET /v1/data` upgrades to a WebSocket of data-wire frames (`../../libs/sync/PROTOCOL.md`). Each request's permit is verified in Rust against `HOSTING_ROOT` at the edge's clock, and the request kind must match its scope (Read takes ReadEvents, ReadBodies or ReadControls). The log, range and body list come only from the verified permit; the log object is `LOG.idFromName(<kind:u8 || id:32 hex>)`. Read events, and read controls, each return one Events frame; read bodies returns one Body frame per body in permit order, only for bodies the object reports `ordered`, read from R2, and ends with `Refused{Missing}` at the first other; stage returns Staged; StoreHomeObjects returns the 71-byte HomeObjectsStored after the exact durable write; append returns Acked, whose Ack and, for a base log, observed-head receipt are signed from the object's durable result with the configured receipt key. Subscribe sends a Head frame (with a receipt for a base log) for each head notice strictly after its `after` cursor. A newer Subscribe for the same log on the same socket replaces the older one; that is how a device renews before the deadline. At most 64 subscriptions and 8 requests in flight per socket; beyond that a request is refused `Unavailable`. A socket is charged its lasting cost against the isolate's memory budget (below) at its first verified permit, never at the upgrade, so sockets that present no valid permit cost it nothing: a socket with no verified permit 5 s after opening closes with 1008, and Credit does not extend that. Before admission, a refused request closes the socket with 1008 after its refusal, and no request behind it is verified, so such a socket costs at most one permit verification. When the budget cannot take it, the request carrying a socket's first verified permit is refused `Unavailable` and that socket closed with 1013; so is a request on a socket not yet admitted whose frame the budget cannot hold, before its permit is verified, while on an admitted socket only that request is refused. An admitted socket with no request in flight and no subscription for 10 s closes with 1000; only a request whose permit verifies for its kind restarts that time, so neither Credit nor a refused request keeps a socket open. Every close, whatever its cause, returns everything the socket held to the budget once.
- PresenceJoin (version 2, tag 33) takes a presence permit for a base log and opens the log object's `/presence` socket at the permit's epoch; a refused epoch answers `Refused{Epoch}`. A presence socket is charged like any other data socket, and each join like a subscription. A newer join for the same base replaces the older: at the same epoch it only takes the new id and deadline and keeps the upstream socket; at another epoch it reopens. A join ends with one refusal under its current id: `Expired` at its deadline; `Epoch` whenever the log object orders a control, even one that keeps the epoch, so a device rejoins at once after `Refused{Epoch}` rather than wait for a new epoch; `Unavailable` when the object restarts, or when the join's Peers back up (a 17th waiting for window, or one still waiting at the deadline it was queued under, before a renewal), so the device rejoins for a fresh roster. Presence (tag 34) carries 1–512 opaque bytes under the join's id and is answered by nothing: it is forwarded as-is while the join is current, at most 10 a second after a burst of 20, and otherwise dropped, as is an empty one; more than 100 drops in a minute closes the socket with 1008, and more than 512 bytes with 1009. Another device's frame is sent as Presence (tag 35, `from:u32` slot) only if no frame on the socket is waiting, no small frame in the isolate is waiting for the budget, and the window and budget cover it now, else dropped, so content never queues behind presence. Roster changes are Peers (tag 36: `others:u16`, event 0 snapshot, 1 joined or 2 left, `slot:u32`) through the normal window, so a newly joined slot's first Presence can arrive before its `joined` Peers. Presence bytes and slots are never logged.
- Before every Events, Body, Staged, Acked, HomeObjectsStored or Head frame, the edge checks that frame's permit deadline. Past it, or when a subscription's deadline arrives, the frame is withheld and only that request id ends with `Refused{Expired}`; other requests and subscriptions on the socket continue and the socket stays open. A withheld Staged, Acked or HomeObjectsStored does not undo the stage, commit or immutable write, so after `Expired` on an append the device learns its outcome by exact retry under a fresh permit.
- Each data socket has a send window, starting at one largest frame plus 4 MiB, which the device extends with Credit frames. Every data frame waits, first come first served on its socket and, for the budget, across the isolate, until the window and the isolate's memory budget cover its encoded length and then takes it; Refusals take none. However much window a device grants, a socket has at most one initial window of frames taken and not yet credited back. A Body frame's length is the object's stored length, so its body is read from R2 only once the window covers it, and only if its deadline has not passed meanwhile. An Events read takes the largest frame its permit's range allows (64 events for read controls) before the object is read and returns the unused part when it sends. So the window bounds the frames the edge builds for a socket and how far it reads ahead of the device's grants: the device's cooperative flow control. It is not a bound on the bytes the runtime may buffer for a peer that grants credit but does not read. A frame still waiting at its permit's deadline ends `Refused{Expired}`. A grant that takes the unused window above 64 MiB closes the socket with 1008. Refusals carry the permit or object refusal reason. A frame that does not decode closes with 1002, a text frame with 1003, a frame over 4 MiB + 64 KiB with 1009 and an internal failure with 1011. Missing or malformed `HOSTING_ROOT`, `RECEIPT_KEY` (hex seed) or `RECEIPT_CERT` (hex certificate under the root) answers 503 to the upgrade.
- **Memory budget.** Each isolate has a budget of 64 MiB, half of the 128 MB Cloudflare documents per isolate ([Workers limits](https://developers.cloudflare.com/workers/platform/limits/)), instead of a socket count. It has two halves of 32 MiB, charged apart so neither can take the other's. Lasting costs take the first: 16 KiB per admitted data socket or authz session and 4 KiB per subscription or presence join, while they last (estimates, not measured). Frames take the second, until given back: every data frame's window take, from before its bytes are read until the device's Credit returns it or the edge refunds it unsent, and every request frame, at twice its length, while it is handled or until its socket closes. Frames of a request over 256 KiB (bulk: catch-up reads, large bodies) may not use the last 8 MiB of the frames half, so Acks, Heads, Peers and small reads keep flowing when bulk fills the rest. Only a full lasting half sheds new sockets (1013, or 503 for authz), subscriptions and joins (`Unavailable`); waiting frames never do. Worked case, all at once in one isolate: an idle device (authz session and a receive lane with one subscription) costs 36 KiB, and one typing (adding a presence socket with a join and an outbox link) 72 KiB, so the lasting half holds 910 idle or 455 typing devices, or a mix; at the same time a catching-up socket holds at most one initial window (8 MiB + 64 KiB) of the 24 MiB bulk part, so two catch up at full speed and a third with most of a window. Under a larger burst further bulk frames wait, first come first served across the isolate and reading nothing for themselves, while each device's Credit frees budget as fast as it receives. So a later body never overtakes another device's earlier 4.2 MB read of 64 events, which behind three catch-ups at 10 Mbit/s waits about a second. A frame still waiting at its permit's deadline ends `Expired`, which clients retry under a fresh permit; new sockets, subscriptions and joins are admitted meanwhile. Presence is dropped only while a small frame waits for the budget, the only time it could delay content. A request frame over 128 KiB, such as a large publish, is bulk too: while the bulk part is full it is refused `Unavailable`, which the outbox retries. So 100,000 typing devices need about 220 isolates' budget in total across Cloudflare's machines; no socket count limits it. While any frame waits for the budget, a data socket that has not credited back, within two minutes, everything it held when its stall time began is closed with 1013 and returns all it held. A stall time begins when a socket begins to hold frames, and again each time it has paid what it owed; credit for only part of it, or frames the edge returns unsent, does not pay it. So sockets that stop crediting, whether hostile or on a dead connection the runtime has not yet noticed, keep waiting frames waiting for at most two minutes after they last paid: one device's four such sockets can hold the whole frames half for that long, during which every data frame on the isolate waits and presence is dropped. That bound is per socket. Permits name a log, not a device, so the edge has no device identity to cap by: a device that keeps opening new sockets, which wait their turn and take budget as the stalled ones are closed, can keep frames waiting on its isolate for as long as it keeps doing so. An honest device credits each frame as it arrives, so it is closed only if its link brings less than a full initial window in two minutes (about 560 kbit/s) while the isolate is short of budget. The budget cannot see the runtime's own send buffers, and does not hold authz frames. Each authz session forwards at most one frame per direction at a time, up to 3.2 MB, within its rate; with the lasting half the only bound on concurrent sessions, about 2,000 sessions per isolate may each forward one such frame, whether proofs before authentication or base read batches after it, which carry no credit.
- `POST /v1/pair/<64 lowercase hex>?side=show|join&index=0-3` stores one opaque message of 1–8,192 bytes and `GET` with the same query returns it (200) or 204 if it is not there yet. The name is the hash of the QR secret; the `PairingRelay` object it names never sees the secret. Indices run without gaps up to four per side; an exact resend answers 204 again, other bytes at a used index or a gap 409, a fifth message 429, a larger message 413, a bad query 400. Five minutes after the first message the relay deletes itself and answers 410 once; a later message starts a fresh relay, so devices bound a pairing's lifetime themselves.
