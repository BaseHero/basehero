# Native sync consumption adapter

This library persists the portable `bh-sync` consumption plan in a separate server SQLite database. It is not a runnable server or a public read endpoint. The database has one complete, non-archived replay index; every stored event retains its ciphertext, original commitment and indexed id/digest. A replay must obtain a *new* signed operation approval to retrieve the original Ack. Reads select exact ciphertext digests and advance the access sequence without moving the common head. A transaction either commits gate, outcome and event together, or releases neither Ack nor body. `last_outcome()` exposes only the latest exact signed approval and durable gate/Ack to a trusted reconciler, not a receipt authenticated to the checker by itself.

The database also holds detached padded bodies in its own SQL table, keyed by the commitment the kernel derives from the exact bytes. Staging one body, reading 1–64 exact bodies and appending a descriptor each consume one access sequence under their own operation domain. A descriptor append fails closed unless the referenced body (the descriptor's first 32 envelope bytes) is already durably staged, and an Ack is released only after the descriptor commits. Repeating an identical stage is idempotent; a failed append may leave an unreferenced orphan body. Bodies remain in SQL until archival is designed. `open()` refuses any storage-schema version other than the current one before mutating; there is no upgrade path.

The trusted host, **not this SQLite library**, must authenticate current account and audience authority, serialize removal/control mutations with approvals, durably mark pending grants before release, provide conservative trusted time, bind approvals to an actual one-use response channel and deliver the result only over that channel. The `Clock` sample occurs before SQL writes and commit. To establish commit-before-expiry, its upper bound must include the remaining transaction and commit time; native SQLite imposes no maximum on that duration, so this increment does **not** establish exact hosted removal deadlines. An arbitrary safety margin is not proof.

The future host must authenticate committed outcomes to the protected lane and resolve outstanding grants before advancing authority: `last_outcome()` aids trusted reconciliation, but this adapter has no incarnation-fence operation. Expiry plus proof that the sequence was not consumed can resolve an abandoned grant only after any in-flight consumption has finished or been excluded, and trusted time under a validated host timing contract proves no later consumption can succeed. Expiry alone never clears uncertainty. Opening the database proves disk continuity, not freshness of any of that authority. No author/epoch/seen-history content verification is done here; devices must verify those before applying content. The event envelope remains opaque to ordinary storage; no member, device, audience or response-channel-to-person index is kept.

The native SQL index grows with full retained history. Moving rows or bodies out of SQL requires complete historical replay lookup and bounded working storage before any deletion; this adapter does not implement archival or batching. This is local native persistence evidence, not a Durable Object, Workers, attestation, remote client or deployed-host test. The `bh-event` sealed-body integration test lives here as a native dev-dependency only; it is not linked into the Worker Wasm module.

Run from the product root: `cargo test --locked -p bh-sync-service`.
